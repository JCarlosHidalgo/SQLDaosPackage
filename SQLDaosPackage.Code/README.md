# SQLDaosPackage
## _SQL databases DAO's package_

A C# / .NET 9 NuGet package that implements the DAO design pattern in the simplest way possible. Currently only the MySQL backend is implemented.

Available on NuGet:

https://www.nuget.org/packages/JuanCarlosHS.SQLDaosPackage

```bash
dotnet add package JuanCarlosHS.SQLDaosPackage
```

## Architecture

### DAO interface hierarchy

The library categorizes DAOs by how many foreign-key relationships their underlying table has. Each interface constrains its entity at compile time through a matching marker (`IEntity`, `ITwoForeignEntity`, `IThreeForeignEntity`):

- `IDao<T>` (root) — `Create` / `ReadAll` / `Update` plus async variants.
- `ISingleDao<T> : IDao<T>` where `T : IEntity` — adds `Read(Guid id)` / `Delete(Guid id)`. Used for tables that have their own primary key (zero or one outgoing foreign key). The property marked with `[Identificator]` **must be named exactly `Id`** — the SQL `WHERE` clauses in `MySQLSingleDao` hard-code that column name, and the base constructor fail-fasts with `InvalidOperationException` if the entity marks a differently-named property.
- `ITwoForeignDao<T> : IDao<T>` where `T : ITwoForeignEntity` — adds `Read(Guid id1, Guid id2)` / `Delete(Guid id1, Guid id2)`. Used for many-to-many join tables whose row identity is a pair of foreign keys.
- `IThreeForeignDao<T> : IDao<T>` where `T : IThreeForeignEntity` — adds `Read(Guid id1, Guid id2, Guid id3)` / `Delete(Guid id1, Guid id2, Guid id3)`. Used for ternary join tables whose row identity is a triple of foreign keys.

### MySQL implementation layer

`MySQLBaseDao<T>` is the abstract base that implements `IDao<T>`. `MySQLSingleDao<T>`, `MySQLTwoForeignDao<T>` and `MySQLThreeForeignDao<T>` extend it and implement the corresponding sub-interface. **Consumers subclass one of those three** — they never touch `MySQLBaseDao` directly.

A consumer subclass must:

1. In its constructor, assign `_connection` (a `MySqlConnection`) and `_tableName`.
2. Override the two `abstract` methods on the base:
   - `MapReaderToEntity()` — read one row from `_mySqlReader` into a `T` using the tipped `MySqlDataReader` accessors (`GetGuid`, `GetString`, …).
   - `MapReaderToEntitiesList()` — iterate `_mySqlReader` and produce `List<T>`; this is what `ReadAll()` returns. Optionally override `MapReaderToEntitiesListAsync()` to use `ReadAsync` per row.

That is enough for the standard `MySQLSingleDao<T>` flow. `INSERT` and `UPDATE` text are generated by the base `virtual` methods `CreateCommandIntoStringBuilder(T)` and `UpdateCommandIntoStringBuilder(T)`, which walk the columns resolved from the entity attributes and format each value through `MySqlLiteralFormatter`. Override them only when you need custom SQL (stored procedures, computed columns, batch inserts).

The default `UPDATE` requires a single `[Identificator]` column — it filters by that key. Entities without `[Identificator]` (i.e. `MySQLTwoForeignDao<T>` / `MySQLThreeForeignDao<T>` subclasses, whose row identity is the FK tuple) must override `UpdateCommandIntoStringBuilder`; otherwise the base throws `InvalidOperationException` at the first `Update` call. The default `INSERT` works for every entity shape.

`MySQLTwoForeignDao<T>` and `MySQLThreeForeignDao<T>` **resolve the foreign-key column names by reflection** in their base constructor, from the entity properties marked with `[FirstForeignId]`, `[SecondForeignId]` and `[ThirdForeignId]`. Subclasses do not have to assign `_firstForeignKey` / `_secondForeignKey` / `_thirdForeignKey` manually — they only need to override those protected fields if the column name in MySQL diverges from the property name on the entity.

`MySQLBaseDao` also exposes `GetCommandStoredProcedure(name)` so subclasses can add stored-procedure methods on top of the base CRUD surface.

### Entity attributes

Entity properties drive column discovery: an internal resolver walks the public instance properties at first DAO instantiation, classifies each one through the attribute it carries, and caches the descriptor list per CLR type. Every persisted property **must** carry exactly one of the markers below — a missing attribute fails fast with:

> `Property 'Namespace.Entity.PropertyName' must carry either a type attribute ([Text], [Integer], …), a role marker ([Identificator], [FirstForeignId], [SecondForeignId], [ThirdForeignId], [Identifier]) or [NotPersisted].`

**Role markers** (identify what the property represents in the row):

| Attribute | Role |
| --- | --- |
| `[Identificator]` | Primary-key Guid column on a single-entity table (consumed by `ISingleDao<T>`). |
| `[FirstForeignId]` | First foreign-key column on a two-/three-foreign join table. |
| `[SecondForeignId]` | Second foreign-key column on a two-/three-foreign join table. |
| `[ThirdForeignId]` | Third foreign-key column on a three-foreign join table. |
| `[Identifier]` | Non-PK Guid column (e.g. an outgoing FK on a single-entity table). |

**Column-type markers** (non-Guid columns):

| Attribute | MySQL column type |
| --- | --- |
| `[Text]` | `VARCHAR` / `TEXT`. |
| `[Integer]` | `INT`. |
| `[SmallInteger]` | `SMALLINT` / `TINYINT`. |
| `[BigInteger]` | `BIGINT`. |
| `[Timestamp]` | `TIMESTAMP`. |
| `[PreciseTimestamp]` | `TIMESTAMP(6)` (microsecond precision). |
| `[Date]` | `DATE`. |
| `[Time]` | `TIME`. |
| `[Flag]` | `TINYINT(1)` / `BOOLEAN`. |

**Skip marker:**

| Attribute | Effect |
| --- | --- |
| `[NotPersisted]` | Property is excluded from the resolved column list. |

### Minimal usage example

A consumer DAO for a `User` table (`Id`, `UserName`, `Role`) looks like this:

```csharp
using MySql.Data.MySqlClient;
using SQLDaosPackage.Daos.MySQL;
using SQLDaosPackage.Entities;
using SQLDaosPackage.Entities.Attributes;

public class User : IEntity
{
    [Identificator]
    public Guid Id { get; set; }

    [Text]
    public string UserName { get; set; } = string.Empty;

    [Text]
    public string Role { get; set; } = string.Empty;
}

public class UserDao : MySQLSingleDao<User>
{
    public UserDao(MySqlConnection connection)
    {
        _connection = connection;
        _tableName = "User";
    }

    protected override User MapReaderToEntity() => new User
    {
        Id = _mySqlReader!.GetGuid("Id"),
        UserName = _mySqlReader.GetString("UserName"),
        Role = _mySqlReader.GetString("Role")
    };

    protected override List<User> MapReaderToEntitiesList()
    {
        _entitiesList = new List<User>();
        while (_mySqlReader!.Read())
        {
            _entitiesList.Add(MapReaderToEntity());
        }
        _mySqlReader.Close();
        return _entitiesList;
    }
}

var dao = new UserDao(new MySqlConnection(connectionString));
await dao.CreateAsync(new User { Id = Guid.NewGuid(), UserName = "ada", Role = "admin" });
List<User> users = await dao.ReadAllAsync();
```

`UserDao` does not override `CreateCommandIntoStringBuilder` or `UpdateCommandIntoStringBuilder` — the base generates `INSERT INTO User (Id, UserName, Role) VALUES (...)` and `UPDATE User SET UserName = ..., Role = ... WHERE Id = ...` from the column attributes on `User`. The connection does not need to be opened first; every DAO call routes through `MySQLRetryPolicy.EnsureOpen` / `EnsureOpenAsync`.

For `MySQLTwoForeignDao<T>` and `MySQLThreeForeignDao<T>`, the FK column names are picked up automatically from `[FirstForeignId]` / `[SecondForeignId]` / `[ThirdForeignId]` on the entity — the subclass only assigns `_firstForeignKey` etc. when the SQL column name differs from the entity property name. The default `UPDATE` does not work for those DAOs (no `[Identificator]`), so a join-table subclass must override `UpdateCommandIntoStringBuilder` with its own composite-key `WHERE` clause.

### Retry policy and connection lifecycle

Every MySQL operation is routed through `MySQLRetryPolicy`:

- `EnsureOpen` / `EnsureOpenAsync` — called at the top of every DAO method so consumers can register the connection without eager-opening it. A `Broken` connection is closed first, then reopened.
- `ExecuteAsync` — wraps async operations with exponential backoff (3 attempts, 100 ms initial delay, doubling). Retries only on the curated transient error numbers (lock-wait, deadlocks, network / server-gone-away). Operations passed a non-null `MySqlTransaction` are not retried, since the transaction would already be invalid.

### Injector layer

Independent of the DAO hierarchy. `IDataInjector` / `DataInjector` run an arbitrary MySQL command, intended for `LOAD DATA` bulk loads from `.csv`. Consumers subclass `DataInjector` and set `_injectionCommand` in their constructor. `InjectDataAsync` also goes through `MySQLRetryPolicy`.

## Building with dotnet

Requires the .NET 9 SDK.

```bash
# Restore dependencies
dotnet restore SQLDaosPackage.Code.csproj

# Build the library
dotnet build SQLDaosPackage.Code.csproj -c Release

# Produce the NuGet package (.nupkg lands in bin/Release/)
dotnet pack SQLDaosPackage.Code.csproj -c Release
```

Version, author, and package metadata are defined in `SQLDaosPackage.Code.csproj`.
